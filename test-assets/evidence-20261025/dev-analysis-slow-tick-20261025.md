# 带载慢 tick 劣化 — 开发侧分析（2026-10-25）

数据源：`pi-logs/gateway.log`（4.2MB，38320 条逐 tick 日志）、`pi-logs/audit-20261025-regression.jsonl`（83 条）。
分析人：开发。对应测试报告 §二/§六「带载下规则引擎 tick 劣化」。

## 结论先行

1. **BUG-001（整窗静默）未复现，且检测路径全程健康**：38320 个 tick 无一静默，触发读（TCP 虚拟执行器）全程 ≤14ms；带载下从预置到 fire-exec 开始的检测判定仍 ~0.1–0.5s（例：3.42s 那轮 = 检测 ~0.46s + exec 2957ms）。
2. **慢 tick 不只在负载窗**：11 条慢 tick 中 **5 条落在空载基线批次**（15:16:02 / 15:17:35 / 15:19:02 / 15:23:02 / 15:24:05，2.8–2.9s；对应 fires=3/6/8/12/14），带载窗 6 条（2.0–14.6s）。测试报告「空载时段零告警」需修正为「空载也有，负载放大」。
3. **劣化位置 = `_fire()` 动作段，不是触发读、不是线程调度**：11/11 慢 tick 全是 fire tick；exec（guard+PING 前置+SET，串口）延迟空载 10ms → 带载 876–2957ms；其余时间在 verify 轮询读（串口 GET led）与失败重试（15:16:02 fire 的 5.87s tick = exec 10ms + verify1 失败 ~3.9s + 重试 exec 10ms@15:16:06 + verify2 ~2s）。
4. **延迟指纹 = ~0.8–1.0s 量子**：876/1133/1667/1938/2552/2957 ms 与空载慢 tick 的 2.8s（≈1.6+0.2+1.0 的 verify 读），都吻合「单命令 800ms 超时 + 自动重试一次」。result 全 ok、read_errors=0 → 首试丢失被重试兜住，最终成功。
5. **定性**：串口命令间歇性「首试丢失」（命令或响应在 USB/CDC 链路上丢，重试即恢复）。空载低频发作（约每 2 次 fire 1 次 verify 读慢 ~1.6s）；带载发作频率/深度放大（exec 量子叠加 → 14.6s）。
6. **与 BUG-001 原始形态是两种签名**：当时是检测段整窗静默（fire 根本未尝试），今天是动作段慢但检测零静默。今天数据不能解释 39s 静默，该单保持「原因未知」；当时与今日唯一形态差异仍是双进程双开串口。

## 证据锚点

- 触发读：全日志 `read='…' (Xms)` X 最大 14ms（1078×1ms、52×2ms…封顶 14ms）。
- 14.6s tick（行 38667–38691）：FIRE 判定 15:25:57（read 0ms）→ 审计 exec 15:26:00 lat=2957 result=ok → 重试 exec 15:26:09 lat=1667 → tick 止于 15:26:12。
- 14.6s 窗口内仅 20 个 MCP POST（~1.4/s）→ 泛洪客户端自身被服务端拖慢（自限速），瓶颈在服务端串口命令链路，非客户端压测不足。
- 空载慢 tick 与审计对齐：WARN#1 fires=3 ↔ 15:16:02 fire（exec lat=10ms）+ 15:16:06 重试 exec（lat=10ms）；WARN#2/3/4/5 fires=6/8/12/14 ↔ 15:17:35/15:19:02/15:23:02/15:24:05（exec 均 10ms，无重试 → 时间在 verify 慢读）。
- 测试脚本核过：reg_rounds.py 只碰虚拟执行器 output，不碰 LED，排除测试侧竞争。

## 仪表缺口（下一轮定位「首试为什么丢」所需）

- verify 段逐读日志（当前只有触发读有逐 tick 日志，verify 读完全不可见）。
- 适配器 attempt 级计时 + invalidate/reopen 事件日志（当前超时重试完全静默，重开次数无法对账）。
- stats 增加 verify_reads / verify_slow / adapter_timeouts 计数器。

## 优化候选（都不动固件，供需求侧拍板）

1. 资源读缓存 TTL（如 chip_temp 500ms）：削减串口命令需求，带载收益最大。
2. 重试策略分级：超时后不立即 invalidate+reopen（重开瞬态本身易丢下一命令，可能自激励）；限制 reopen 频率。
3. fire 路径与读路径分离优先级（引擎动作插队）。
4. 若需根治首试丢失：先补上述仪表跑一轮复抓，区分主机 USB/CDC 调度 vs 固件响应延迟。
