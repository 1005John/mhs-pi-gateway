# 设备接入指南 —— 三步把一台新设备纳管进网关

网关的一切能力（MCP tools/resources、护栏、审计、规则联动）都由**设备能力描述符（DCD）**驱动：接新设备不改网关代码，只写一份 YAML。本文用仓库里的真实描述符 `gateway/descriptors/esp32s3-led-01.yaml` 逐段讲解。

## 第一步：写描述符

### device 段 —— 这台设备怎么连

```yaml
device:
  id: esp32s3-led-01          # 全局唯一 ID，审计/规则/CLI 都用它
  name: ESP32-S3 RGB LED 板
  category: usb-serial        # usb-serial | network | virtual
  adapter: serial-msp1        # 网关侧适配器注册名（第二步）
  transport:
    serial: { port: /dev/ttyACM0, baud: 115200 }
  identity:                   # 可选；USB 热插拔重枚举时用于自动匹配
    usb: { vid: "303a", pid: "1001" }
```

- `category: network` 时 transport 换成 `network: { host: ..., port: ..., proto: tcp }`；`virtual` 用于测试桩
- `identity.usb` 强烈建议填：拔插后枚举节点名可能变（ttyACM0→ttyACM1），靠 VID/PID 才能自动重绑

### resources 段 —— 可读状态（自动成为 MCP resources）

```yaml
resources:
  - { name: chip_temp_c, type: float, unit: "°C", access: ro, poll_s: 10 }
  - { name: led_mode,   type: enum, values: [static, blink, cycle, "off"], access: rw }
  - { name: led_color,  type: string, pattern: "^#[0-9a-fA-F]{6}$", access: rw }
```

- `type` 支持 float / int / string / enum；enum 和 pattern 同时是**护栏校验依据**
- `poll_s` 是健康轮询建议间隔；`access: ro` 的资源不会生成写路径

### actions 段 —— 可执行动作（自动成为 MCP tools）

```yaml
actions:
  - name: set_led
    risk: L1                    # 分级决定护栏强度（见下）
    params:
      mode:      { type: enum, values: [static, blink, cycle, "off"], required: true }
      color:     { type: string, pattern: "^#[0-9a-fA-F]{6}$",
                   required_if: { mode: [static, blink] } }   # 条件必填
      period_ms: { type: int, min: 100, max: 10000, default: 2000 }
    preconditions: [ping]       # 前置：探活失败直接 denied/precondition-fail
    timeout_ms: 800
    rate_limit: { max_per_min: 10, cooldown_ms: 500 }
  - name: reset
    risk: L2
    confirm: manual             # L2 需人工确认，不会静默自动执行
```

**risk 怎么定**（规范 §2 判定规则）：

| 级别 | 标准 | 护栏 |
|---|---|---|
| L0 | 纯读 | 仅白名单 |
| L1 | 单设备表现层、可随时改回 | 白名单 + 参数校验 + 限速 + 急停可挂起 |
| L2 | 跨设备影响 / 涉及供电固件网络配置 / 不可逆 | 上述全部 + 人工确认（confirm） |

**禁止清单**不受描述符控制，写死在网关：整机断电、恢复出厂、固件刷写、删除存储数据——写了也载不进来。

### health 段 —— 探活

```yaml
health:
  probe: { method: ping, interval_s: 5, miss_threshold: 3 }   # 连 miss 3 次 → offline
```

offline 后所有带 `preconditions` 的动作 2ms 级被拒（实测值），设备恢复后自动回 online。

### 加载即校验（AC-0）

启动时强校验：缺字段 / 非法枚举 / schema 不合法 → **拒载并报错**，绝带病上线。

## 第二步：选适配器

| 适配器 | 适用 | 协议 |
|---|---|---|
| `serial-msp1` | USB 串口设备（现成） | MSP-1 行协议，见规范 §6 |
| `net-tcp-json` | 网络设备（现成） | TCP + JSON 行协议，见 `virtual_executor.py` |
| 自写 | 其它总线 | 实现 adapters.py 的基类接口即可，护栏/审计/规则层零改动 |

## 第三步：验证

```bash
.venv/bin/python selftest.py        # 32 项自测全绿
.venv/bin/python mcp_smoke.py       # MCP tools/resources 与描述符一一对应
.venv/bin/python gateway.py exec <device-id> <action> --params '{...}'   # 真实链路点验
.venv/bin/python gateway.py audit   # 查审计留痕
```

## YAML 陷阱（踩过的坑）

**裸 `on` / `off` 会被 YAML 1.1 解析成布尔值**，enum 值、参数默认值里必须加引号：`values: [static, blink, cycle, "off"]`。描述符加载器对这类错有校验，但别依赖它——加引号是纪律。
